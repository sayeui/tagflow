# TagFlow 发版验收测试用例

> 用于正式发版前的人工验收。照此清单逐项验证，通过后在「预期」项打勾、在「备注」记录问题。
>
> - **验收版本**：v0.2.0（待发；从 v0.1.0 Beta 升级）
> - **验收环境**：Docker 部署（`docker compose up -d`），真实数据 / 真实文件
> - **与自动化 e2e 的关系**：`tagflow-e2e/` 已覆盖隔离环境的 11 个用例（5 张夹具图 + 2s 扫描间隔 + 仅 chromium）；本清单聚焦 e2e 覆盖不到的**真实环境 / 升级路径 / 长期运行 / 写操作 / 边界**
> - **优先级**：P0 发版必过 · P1 重要边界 · P2 锦上添花

---

## 验收前置

- [x] 已构建 / 拉取待发版镜像
- [x] `.env` 已设置 `TAGFLOW_JWT_SECRET`（≥32B，`openssl rand -hex 32`）与 `TAGFLOW_ADMIN_PASSWORD`（≥12B）
- [x] `./cache` 目录存在且属主 `1000:1000`（缩略图缓存 webp；后端启动自动建目录，但 bind mount 需 host 属主 1000 才能让容器 UID 1000 写入，否则缩略图生成失败）
- [ ] 准备一个真实资源库目录（含图片 / 视频 / 文本 / Markdown / PDF 各若干）

---

## P0 — 发版必过（核心闭环 + 本版本新功能）

### P0-1 全新 Docker 部署
**前提**：干净环境（无旧 `tagflow_data` volume）
**步骤**：
1. `cp .env.example .env`，填写 `TAGFLOW_JWT_SECRET` + `TAGFLOW_ADMIN_PASSWORD`
2. `mkdir -p ./cache && chown -R 1000:1000 ./cache`
3. `docker compose up -d`，等 ~30s
4. `curl http://localhost:8080/api/health`
5. 浏览器访问 `:8080`
**预期**：
- [ ] 容器 `healthy`（`docker ps`）
- [ ] `/api/health` 返回 200
- [ ] 浏览器出登录页
**边界**：
- [ ] `TAGFLOW_JWT_SECRET` <32B 或 `TAGFLOW_ADMIN_PASSWORD` <12B → release 镜像**启动失败**（日志报错退出，debug 构建回退默认值并 warn）
**备注**：__________

### P0-2 Golden Path（核心用户流）
**步骤**：
1. 登录（admin + 设置的密码）
2. 资源库页「添加」→ Local + name + 真实路径 →「测试连接」→ 保存
3. 点「触发扫描」
4. 回首页 → 卡片网格 → 切「列表视图」→ 搜索框输入中 / 英文关键词 → 点卡片开预览抽屉
**预期**：
- [ ] 建库成功，扫描中提示，完成后文件数正确
- [ ] 网格 / 列表切换正常，虚拟滚动 + 无限滚动流畅
- [ ] 搜索按文件名过滤（中英文均生效）
- [ ] 预览抽屉打开（图片 / 视频 / 文本 / Markdown / PDF）
**边界**：
- [ ] 路径不存在 / 无读权限 → 拒绝建库（不建幽灵空库）
- [ ] 扫描进行中再次「触发扫描」→ 409「正在扫描中」Toast
**备注**：__________

### P0-3 升级路径（重点 — e2e 完全未覆盖）
**前提**：保留 v0.1.0 Beta 的 `tagflow_data` volume（含真实历史库 + 文件 + 标签）
**步骤**：
1. `docker compose down`
2. 切到待发版镜像（`git pull` 或换 image tag）
3. `docker compose up -d`
4. 查启动日志 `docker logs tagflow`
5. 登录验证历史数据
**预期**：
- [ ] 自动跑迁移，无报错
- [ ] `backfill::run_if_needed` 按 `app_meta.tagger_version` 回填历史文件的 type/ext/time 标签（debug 日志可见）
- [ ] 已有库、文件、标签树全部保留
- [ ] 缩略图缓存可继续用 / 可重建
**备注**：__________

### P0-4 定时增量扫描（本版本新功能 — 重点）
**前提**：`.env` / compose 临时设 `TAGFLOW_SCAN_INTERVAL=60`（加速验证；正式部署改回 3600）
**步骤**：
1. 建库后**不点扫描**，等 ≤60s
2. 观察前端「最后扫描」时间是否自动出现（证明首轮立即扫）
3. 往库目录 `cp` 一个新图片 → 等 ≤60s → 刷新首页
4. `rm` 一个文件 → 等 ≤60s → 刷新首页
5. 观察前端「预计下次扫描」时间
**预期**：
- [ ] 首轮无需手动触发即扫描（「最后扫描」自动出现）
- [ ] 新增文件下一轮自动入库
- [ ] 删除文件下一轮自动移除
- [ ] 「预计下次扫描」= 上次 + 60s，且随轮次推进
**边界**：
- [ ] 扫描中手动触发 → 409 提示
- [ ] `TAGFLOW_SCAN_INTERVAL=10` → 实际生效 60（clamp）
- [ ] `TAGFLOW_SCAN_INTERVAL=abc` → 回退 3600
**备注**：__________

### P0-5 缩略图（真实 ffmpeg）
**步骤**：
1. 库含 `.jpg/.png/.webp/.mp4/.mov`
2. 扫描后等 worker（5s 轮询）处理
3. 浏览查看缩略图，滚动加载
**预期**：
- [ ] 图片 + 视频缩略图（webp）生成
- [ ] 卡片显示缩略图（非占位图标）
- [ ] 滚动时懒加载、无错位 / 重叠
**边界**：
- [ ] `docker exec tagflow which ffmpeg` 确认在 PATH
- [ ] ffmpeg 缺失 → 缩略图任务 Failed（warn 日志），前端回退图标，服务不崩溃
**备注**：__________

### P0-6 认证与安全
**步骤**：
1. 登录 → 设置页改密码（先试 `<12B`）
2. 改密码成功 → 旧 session 是否失效
3. 等 JWT 过期（24h，或换 `TAGFLOW_JWT_SECRET` 触发）→ 访问
**预期**：
- [ ] 密码 <12B 被前端 + 后端双重拒绝
- [ ] 改密成功后旧 token 立即失效（需重新登录）
- [ ] JWT 过期 / 换密后自动重定向登录页
**备注**：__________

## 已知限制（发版说明应列出）

- WebDAV 资源库未实现（v0.3 计划）
